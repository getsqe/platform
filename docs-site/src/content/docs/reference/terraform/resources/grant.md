# chameleon_grant (Resource)

Manages a SQL-style GRANT/REVOKE statement against a Chameleon resource. Each resource maps to one (privilege, resource, grantee, effect) tuple — analogous to `GRANT <privilege> ON <resource> TO <grantee>`. The BFF has no PATCH endpoint for grants, so every settable field forces replacement: changes are persisted as revoke-then-grant. Deny effects override allow effects of equal scope.

## Example Usage

```terraform
# GRANT SELECT ON main_warehouse.analytics.* TO GROUP SG-DataAnalysts
#
# A `chameleon_grant` is a SQL-style GRANT statement. Each resource maps to
# exactly one (privilege, resource, grantee, effect) tuple. Every settable
# attribute forces replacement — there is no PATCH endpoint upstream, so any
# change is applied as revoke-then-grant by Terraform.
resource "chameleon_grant" "data_analysts_can_read_analytics" {
  privilege = "SELECT"

  catalog   = "main_warehouse"
  namespace = "analytics"
  table     = "*" # supports `*` and `%` wildcards

  grantee_type = "GROUP" # GROUP (Polaris role / Keycloak group) or USER
  grantee_name = "SG-DataAnalysts"

  effect = "allow" # `allow` (default) or `deny` — deny wins on conflicts
}

# Workspace-scoped grant: pass `workspace_slug` instead of `catalog` to grant on
# the workspace's own catalog, and target one of its auto-provisioned groups
# (`ws-<slug>-members` / `-admins`). This is how the multi-tenant demo gives a
# tenant's members read access to their `public` namespace.
resource "chameleon_grant" "team_a_members_read_public" {
  privilege      = "SELECT"
  workspace_slug = chameleon_workspace.team_a.slug
  namespace      = "public"
  table          = "*"
  grantee_type   = "GROUP"
  grantee_name   = chameleon_workspace.team_a.member_group
  effect         = "allow"
}
```

## Schema

### Required

- `grantee_name` (String) Group/role/username this grant applies to.
- `grantee_type` (String) `GROUP` (Keycloak group / Polaris role) or `USER` (Keycloak username).
- `privilege` (String) SQL-style privilege: `USE`, `SELECT`, `MODIFY`, `CREATE`, `DROP`, `MANAGE`, or `ALL`.

### Optional

- `catalog` (String) Warehouse (catalog) name. Mutually exclusive with `workspace_slug` — set exactly one.
- `effect` (String) `allow` (GRANT) or `deny` (explicit REVOKE-style block). Default `allow`. Deny wins when an allow and a deny apply to the same resource.
- `namespace` (String) Namespace path inside the catalog. Omit for a catalog-level grant. Supports `*` and `%` wildcards.
- `table` (String) Table name inside the namespace. Omit for a namespace-level grant. Supports `*` and `%` wildcards.
- `workspace_slug` (String) Slug of a workspace to target instead of `catalog`; resolves to the workspace's primary catalog (`ws_<slug>` with hyphens as underscores). Mutually exclusive with `catalog` — set exactly one.

### Read-Only

- `granted_at` (String) RFC3339 timestamp of when the grant was issued.
- `granted_by` (String) Username of the principal who issued the GRANT.
- `id` (String) Server-assigned UUID.
- `resource_key` (String) Dot-joined fully-qualified resource (`catalog.namespace.table`, with `*` for wildcards).
- `resource_type` (String) Derived: `CATALOG`, `NAMESPACE`, or `TABLE`.
