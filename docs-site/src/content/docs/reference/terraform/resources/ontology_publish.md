# chameleon_ontology_publish (Resource)

Validates and publishes an existing ontology version (`draft → validated → published`). Publish must happen **after** the version's entity types, attributes, relations, and mappings exist — so this is a separate resource you can order **after** that content with `depends_on`, rather than `chameleon_ontology_version.publish` (which runs at version-create time, before content, and would validate an empty draft). Keep the version's own `publish = false` and use this instead for a reliable single-apply publish.

One-shot: `version_id` forces replacement, so pointing at a new version re-publishes. `terraform destroy` is a no-op upstream (the BFF has no un-publish); it only drops the resource from state.

## Example Usage

```terraform
# Publish an ontology version AFTER its content exists. Keep the version a draft
# (publish = false) and order this resource after the entity types / attributes /
# relations / mappings with depends_on — publishing an empty draft fails, and the
# version's own `publish` runs at create time (before content).
resource "chameleon_ontology_version" "v1" {
  name    = "ecommerce-v1"
  publish = false
}

# ... chameleon_ontology_entity_type / _attribute / _relation / _mapping here ...

resource "chameleon_ontology_publish" "v1" {
  version_id = chameleon_ontology_version.v1.id

  # List the leaf mappings (and anything else) so publish runs last.
  depends_on = [
    chameleon_ontology_mapping.attributes,
    chameleon_ontology_mapping.order_table,
  ]
}
```
