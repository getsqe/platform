# chameleon_ontology_version (Resource)

Creates an ontology version (draft). Entity types, attributes, relations, and mappings are all scoped to a version_id — every other `chameleon_ontology_*` resource takes that id as input.

Set `publish = true` to validate then publish the draft on apply. Publishing transitions the version through `draft → validated → publishing → published` and the previously-published version is auto-archived by the BFF.

**Caveat:** the BFF doesn't expose a DELETE endpoint for versions. `terraform destroy` removes the version from state with a warning; the upstream record (along with all entities/attributes/relations that lived in it) remains. Archive via the UI or BFF if you need true cleanup.

## Example Usage

```terraform
# A draft ontology version. Set `publish = true` to validate + publish
# in one apply. Leaves the previously-published version archived.
resource "chameleon_ontology_version" "v2" {
  name    = "ecommerce-v2"
  publish = false # flip to true once entities/attributes/relations are ready
}
```

## Schema

### Optional

- `name` (String) Optional human-readable name for the draft.
- `parent_version_id` (String) Optional id of a published version to clone from. Leave unset to start an empty draft.
- `publish` (Boolean) When `true`, the BFF's validate + publish endpoints are called after Create. The version transitions to `published`. Default `false` leaves the version in `draft` so additional edits can be made.

### Read-Only

- `created_at` (String) RFC3339 creation timestamp.
- `id` (String) BFF-assigned UUID of the version.
- `published_at` (String) RFC3339 publish timestamp; empty while the version is still a draft.
- `status` (String) Current lifecycle state: draft / validated / publishing / published / archived / failed.
